# Theme night step 1: CI workflow and branch protection

## What was decided

The PR gate set is one GitHub Actions job named `ci`. That job is the status check branch protection will require. Its sequential steps are the gates:

- `npm test`
- `npm run typecheck`
- `npm run build -w apps/client`
- `npm run docs:smoke`

Root `package.json` now runs `npm test --workspaces` and `npm run typecheck --workspaces`, so those two commands cover `packages/contracts`, `apps/client`, and `apps/gateway`.

The workflow file is `.github/workflows/ci.yml`. Triggers are `pull_request` and `push` to `main`. One job, `ci`, on `ubuntu-latest`, Node 22 via `actions/setup-node@v4` with npm cache, then `npm ci`, then the four gates.

Step 8 can add a sibling `pages` job in the same file with `needs: ci` and `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`. That does not rename or split `ci`, so branch protection stays pointed at the same check.

Post-merge, set protection with this command and `/tmp/theme-night/01-ci/protection.json`:

```
gh api -X PUT repos/yuri-poliantsev/lorien-stack/branches/main/protection --input /tmp/theme-night/01-ci/protection.json
```

The JSON body is:

```
{
  "required_status_checks": {
    "strict": false,
    "contexts": ["ci"]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
```

`strict` is false because many owners open PRs off the same `main` tonight. If GitHub required each head to include the latest `main` commit, every merge would force the remaining owners to rebase before they could merge, and the night would serialize. `required_pull_request_reviews` is null because there is no human reviewer tonight. The coordinator swarm-verifies, then an admin merges through `gh`.

## What was rejected and why

An explicit `-w packages/contracts -w apps/client -w apps/gateway` list was rejected. `--workspaces` already covered every current workspace, and a new workspace with a `test` or `typecheck` script joins the gate without a root edit. `--if-present` was rejected so a workspace that forgets those scripts fails CI rather than disappearing from the gate.

A GitHub Actions `strategy.matrix` of OS or Node versions was rejected. The named data shape is the gate list inside one job named `ci`. Extra matrix cells would create extra required-check names and would force a protection rewrite later.

A comment in `ci.yml` that points at the future `pages` job was rejected. Comments in the workflow do not earn their place. This entry records the hook instead.

`strict: true` was rejected. See above. Required reviewers were rejected for the same reason.

Origin CLI is installed at `/Users/iuriipoliantsev/.local/bin/origin`. The owner brief forbids it. Forge stays `gh`.
